# xLLM 可观测性研究：实验环境与进入方式

## 1. 记录范围

- 记录日期：2026-10-16。
- 用途：记录 xLLM 监控指标核验、请求链路耗时分析和瓶颈研究所使用的实验环境。
- 信息来源：用户提供。本次仅记录环境信息，未连接服务器、进入容器或运行实验。
- 以下命令是**登录服务器和进入容器的方式**，不是 xLLM 模型服务的完整启动命令；实际服务启动参数尚待补充。

## 2. 进入实验环境

在本地终端登录服务器：

```bash
ssh <dev-host>
```

登录服务器后，进入已有容器：

```bash
docker exec -it <xllm-container> /bin/bash
```

上述流程进入已有容器，不包含创建或启动容器的步骤。

## 4. 源码与构建基线约定

- 本地目录 `<repo-root>` 用于当前源码阅读和研究记录；后续实现修改以服务器源码为工作基准。
- 先核验服务器状态，再决定如何同步修改；不直接用本地目录覆盖服务器目录，不丢弃服务器已有改动。
- 用户已说明现有构建可直接使用。后续若修改源码，需按实际构建流程更新相关产物，并确认运行进程加载了新产物，不能仅凭源码改变认定实验已使用新逻辑。
- 每轮实验记录服务器源码提交、未提交改动、brpc 子模块版本、构建产物与完整启动参数，保证指标数值可追溯到实际运行版本。

## 5. 正式实验前待补充的信息

1. 容器内源码绝对路径、当前分支、提交与未提交修改；brpc 子模块实际版本。
2. 构建目录、xLLM 可执行文件绝对路径、编译配置，以及现有产物对应的源码版本。
3. 本轮使用的具体模型目录、模型标识、精度与完整服务启动命令。
4. 服务监听地址和端口、客户端所在位置、监控抓取方式及抓取间隔。
5. 实际设备型号与数量、可见设备、TP/DP 等并行配置、CPU 和内存限制、其他进程占用情况。
6. 请求类型、输入/输出长度、并发与流式设置；overlap、graph、调度和 KV cache 等影响统计边界的配置。
